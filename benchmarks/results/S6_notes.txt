Numerics (deviation from A5, documented): A5's fp8 code-point rule (<=1 code on <=0.5%) is unusable
  across implementations with different bf16 rounding points / GEMM split-K (code diffs near zero are
  many code points but tiny in value).  Used instead: dequantized value vs reference (fp64 projections,
  fp32 elementwise, bf16 rounding at the materialization points), error / row amax <= 32/448 (~1 code at the
  top binade); ue8m0 scale 2x flips reported, not failed; weights rtol 1e-2; untouched cache bytes must be
  identical (all arms: 0 bytes differ).  AITER-writer arms are checked against a no-Hadamard reference.
  T: passes everywhere except weights on the adversarial (seed 100, cancelling-projection) draw at
     m128/m256 (0.17% of weights beyond rtol 1e-2) -- B fails the same check on ~95%.
  B (AITER): fails on most shapes: k cache error up to 0.09-0.10 x amax on benign data (m>=2) and
     0.36-0.50 x amax on seed 100; gate weights 17% beyond rtol 1e-2 on benign data.  Root cause measured
     directly: AITER's bf16 GEMM for (N=128/32, K=6144) at m16 (flydsl hgemm ks8 via tgemm) differs from
     correctly-rounded bf16 in 61% of outputs, max abs 0.026 vs torch F.linear 0.0078 (fp64 ref).  m1
     (skinny) is exact.  So no "T fails while B passes" blocker.
  X_fused (SGLang HIP): bit-identical codes to T on seed 0; passes.
