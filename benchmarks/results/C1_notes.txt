ARMS
decode : T = templated row of the fp8 TP4-EP4 profile (rows 1..16 split_r3::paged_gqa_attention_ep4,
         rows 32/64 r3::paged_gqa_attention); Ttp4 (rows 4, TP4 profile tp4 entry);
         B = paged_attention_ragged with SGLang's bucket partitions; B2 = same op with
         ceil(max_seq/256) partitions; B1 = unified_attention (q fp8 quant counted, 2-D page
         table built outside the graph, as SGLang's metadata step does).
         kv_indices = 256*65536 entries (graph capacity, as served) -- the templates key their
         schedule on kv_indices.numel()/sequences.
prefill: T = paged_gqa_prefill_r3_template::paged_gqa_attention with q_scale = k_scale (binder);
         B = scaled_fp8_quant + mha_batch_prefill_func (SGLang); B1 = unified_attention.

FINDINGS SO FAR
- Tight kv_indices (numel = live tokens, ctx 16k): T cannot run -- split_r3 e9 raises
  "capacity 16384 outside the served bucket", r3 rows 64 raises "not a validated instance".
  The templates only serve the CUDA-graph-capacity layout; an upstream op would need a
  schedule keyed on the live length (or max_seq) instead of kv_indices.numel().
- Decode numerics (block 0, rows 1/4/64 @16k, 1 @2k, seeds 0 and 100): T, Ttp4, B, B1, B2 all
  PASS; T max_abs 3e-5..2.3e-4 vs B 3.5e-4..3.9e-3 (T ~10x closer to the fp32 reference).
- Prefill numerics: T FAILS the bf16 criterion on the benign draw (seed 0) at p1024/p4096/
  p6143/p8192/p4096x4 while B and B1 pass: 0.08% of elements, confined to the first ~40 query
  rows (causal rows that see < ~40 keys), max_abs 0.10-0.19 vs B 0.02-0.03; rows >= ~500 have
  error 0.007-0.01 vs B 0.002.  With an 8192-token prefix (p8192x1+8192) T passes.  On the
  cancellation draw (seed 100) all arms fail (B too), T worse (0.23-0.51 vs 0.08-0.11).
  Per the stop rule this is a T-fails-while-B-passes numerics blocker for the prefill member.
